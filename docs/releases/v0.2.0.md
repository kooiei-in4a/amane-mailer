## Included changes since v0.1.1

- Admin tenant-scope authorization for multi-user operators (#91).
- ADR 0015: frozen manual retry/cancel state transitions (#100).
- Admin manual retry and manual cancel with `Cancelled` worker status and DB
  migration 007 (#101).
- `admin user` CLI for scoped and break-glass Admin user creation (#131).
- Docker build context hardening to exclude tenant secrets and backups (#117).
- Admin masked mode subject/reply-to PII masking consistency (#118).
- README / SECURITY / runbook Admin security sync (#119).
- Publish-image workflow release-critical gates (#120).
- Admin tenant-scope operational boundary docs (#121).
- Metadata value secret policy documentation (#122).
- CI arm64 frequency reduction, Dependabot Actions updates, develop protection
  policy documentation.

The public `POST /internal/mail-requests` HTTP contract shape and acceptance
semantics are unchanged. OpenAPI documents metadata value policy; runtime
validation behavior is unchanged from v0.1.1.

Operators upgrading existing SQLite deployments should allow a normal service
restart so migration 007 can apply the expanded `Cancelled` status constraint.

## Known limitations

- Published runtime image is a multi-arch index (`linux/amd64`, `linux/arm64`).
- SQLite deployment assumes a single node / single replica.
- Admin UI remains disabled by default, internal-network-only, and experimental.
- Manual retry/cancel and tenant scope are Admin/CLI features; they do not extend
  the public mail-request HTTP API.
- `202 Accepted` means the request was persisted; provider delivery completes asynchronously.
