## Included changes since v0.9.0

### Reliability

- Prevent duplicate provider send after finalize loses the processing lease, and
  keep delivered evidence when a reaper already terminalized the request (#238).
- Fail `/readyz` when worker or sweep heartbeats are stale (#241).
- Classify `SQLITE_FULL` as `STORAGE_FULL` with disk / retention runbook guidance
  (#244).
- Drain in-flight webhook deliveries on graceful shutdown (#245).

### Maintainability / docs

- Split `MailRequestRepository` into focused store types (#242).
- Document delivery uniqueness guarantees (#239).
- Implementation status manifest + CI format check (#250, #252).
- ADR 0013/0014/0015 implementation status refresh (#240).
- Cancel vs worker claim race regression tests (#243).

### Contracts / OpenAPI

- `Amane.Mailer.Contracts` and OpenAPI `info.version` aligned on `0.9.1`
  (patch bump; no new consumer HTTP contract surface).

## Known limitations

- SQLite deployment assumes a single node / single replica.
- Admin UI remains disabled by default, internal-network-only, and experimental.
- `202 Accepted` means the request was persisted, not that provider delivery
  completed.
- Delivery is at-least-once. If the service stops after provider send succeeds
  but before the database records delivery, the same mail may be sent again.
  v0.9.1 narrows one finalize/reaper race that previously risked an extra send
  after a successful provider response.
- Webhook endpoints are optional per tenant (one URL per tenant in this release).
- Consumer SDK status polling helpers are not yet included (HTTP GET is available;
  SDK Phase 2 follow-up).
- No template engine.
- No full multi-recipient support.
