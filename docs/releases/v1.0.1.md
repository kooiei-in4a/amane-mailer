## Positioning

- Patch release on the 1.0.x line. Fixes four webhook-delivery defects found
  after v1.0.0.
- **No HTTP contract change.** `docs/api/openapi.yaml` schemas and
  `Amane.Mailer.Contracts` types are unchanged; only `info.version` and the
  package `Version` move to `1.0.1`. Upgrading requires no consumer action.

## Included changes since v1.0.0

### Webhook delivery reliability

- **#388** — Converge webhook delivery events whose lease expires on the final
  attempt into `DeadLettered`. Both the claim path and the pending-work query
  require `attempt_count < max_attempts` for the expired-`Delivering` branch, so
  these rows were unreachable: never re-delivered, never converged, and
  permanently counted in `mail_webhook_events_pending`.
- **#389** — Isolate `WebhookDeliveryWorker` failures per event. A malformed
  `payload_json` or an unclassified claim / deliver / finalize exception could
  fault the whole `BackgroundService` and stop all subsequent delivery. Invalid
  JSON now converges to `WEBHOOK_PAYLOAD_INVALID` as a terminal failure, and
  isolated failures apply a bounded backoff instead of retrying immediately.
- **#402** — Stop the idle hot-spin and wake explicitly for scheduled retries.
  The capacity-1 work signal was never drained, so once signalled the claim loop
  span on SQLite write transactions. The idle wait is now bounded by the
  configured initial retry delay.

### Admin / consumer consistency

- **#390** — Keep a committed admin cancel from failing on its post-commit
  webhook enqueue. After the cancel and its success audit had committed, an
  enqueue fault or a client disconnect still propagated out of the handler, so
  operators saw `500` or a dropped connection while the row was already
  `Cancelled`, and a retry then returned `Conflict`. Consumer and admin cancel
  now share one post-commit helper that takes no caller token.

### Security / privacy

- **#389** — Keep unclassified exception text out of webhook worker logs.
  Logging providers render exceptions via `ToString()`, so a deliver-stage
  exception could carry the webhook URL or payload fragments into logs. The
  exception object now reaches the logger only for SQLite faults; everything else
  records the exception type name. The same rule applies to the post-commit
  enqueue warning added in #390.

### Operational behavior worth knowing before upgrading

- Webhook retry wake-up granularity changed. Before #402 the idle spin polled due
  retries with essentially zero latency; the worker now polls at most one wake
  interval late, bounded by `Mailer:Webhook:InitialDelaySeconds` (default 10s).
  Against the default backoff schedule (10 → 20 → … → 300s) this is not
  operationally significant, and `WebhookDeliverySweepService` (15s) supplies
  additional wake-ups.
- Idle CPU usage drops substantially on hosts where webhook delivery is
  configured. This is the #402 fix, not a regression.

### Documentation

- **#300** — Adds [ADR 0020](../adr/0020-bounce-ingestion-and-suppression.md),
  the bounce ingestion and suppression design for v1.1.0. Records the Pull
  transport decision, the `provider_message_id` ↔ `data.messageId` correlation key
  confirmed against real ACS resources (#299), and the PII handling required for
  provider delivery reports. Nothing in this release's runtime behavior depends on
  it; the feature is registered as `planned` in `docs/implementation-status.json`.

## Known limitations carried forward from v1.0.0

- `202 Accepted` means the request is persisted, not that provider delivery
  completed.
- Delivery is at-least-once. A stop between provider success and the `delivered`
  update can resend the same mail.
- SQLite deployment is single-node / single-replica. See
  [ADR 0019](../adr/0019-sqlite-single-process-boundaries.md).
- Admin UI is disabled by default, experimental, and not intended for direct
  internet exposure. See
  [ADR 0013](../adr/0013-admin-threat-model-and-pii-policy.md).
- Publish workflow hardening (#23) is still open. Tag / version consistency,
  `release` environment alignment, and SBOM / provenance / digest tracking are
  verified manually for this release rather than guaranteed by automation.
