### `linux/arm64`

| Field | Value |
| --- | --- |
| Status | `NOT RUN` (host environment limitation, not an image defect; v0.3.0-only follow-up #188 closed without execution) |
| Date | 2026-07-05 JST |
| Image | `ghcr.io/kooiei-in4a/amane-mailer:v0.3.0` |
| Image digest | `sha256:3eb5bcab6057c611dd6806b4fe6d76fc0e922027e27d4a8ae5c5f8a9a2df07a7` (`linux/arm64` runtime manifest) |
| Environment | `scripts/release-smoke.sh` via Git Bash on Windows, Docker Desktop, `MAILER_IMAGE_PLATFORM=linux/arm64` |

`mailer-migrate` failed to start with `exec ./Amane.Mailer: exec format error`.
This Docker Desktop host has no `linux/arm64` emulation registered (confirmed
with a generic `arm64v8/alpine` image, which fails identically with
`exec format error`), so no `arm64` container can run here regardless of
image content. This is an amd64-only host limitation, not evidence of an
`arm64` runtime defect.

Per maintainer decision, this follows the same precedent as the v0.2.0
release record, where only `linux/amd64` was smoked and `linux/arm64` was
not exercised. `linux/amd64`-only release-image smoke is accepted as
satisfying issue #179. A dedicated `v0.3.0` `linux/arm64` follow-up
([#188](https://github.com/kooiei-in4a/amane-mailer/issues/188)) was closed
when `v0.4.0` became the latest release. Arm64 smoke from `v0.4.0` onward
is tracked in
[#212](https://github.com/kooiei-in4a/amane-mailer/issues/212).

## Known limitations

- SQLite deployment assumes a single node / single replica.
- Admin UI remains disabled by default, internal-network-only, and experimental.
- `202 Accepted` means the request was persisted, not that provider delivery
  completed.
- Delivery is at-least-once. If the service stops after provider send succeeds
  but before the database records delivery, the same mail may be sent again.
- No webhook delivery result API.
- No template engine.
- No full multi-recipient support.
