## Included changes since v0.9.1

### Reliability / operations

- Fail fast on Worker / Webhook / Sweep / Retention / Healthcheck numeric
  misconfiguration instead of silent clamping (#329).
- Require metrics bearer token outside Development when metrics stay enabled
  (#283).
- Map provider delivery failures to a stable `error_code` taxonomy (#279).

### Observability

- Record a fixed primary `/readyz` failure reason via transition-only logs and
  Prometheus gauges `mail_ready` / `mail_readiness_failure` without changing the
  public HTTP contract (#330).
- Include structured `RequestId` and `TenantId` on Worker and
  ExpiredProcessingReaper request logs (#285).

### Admin hardening

- Enforce Admin PBKDF2 password-hash parameter bounds (#281).
- Parse Admin boolean and positive-integer environment variables strictly (#280).

### Contracts / OpenAPI

- `Amane.Mailer.Contracts` and OpenAPI `info.version` aligned on `0.9.2`
  (patch bump; no new consumer HTTP contract surface).

### Migration

- DB migration 010 adds nullable `admin_audit_events.tenant_id` (#282). Applied
  automatically via `db migrate` / normal startup; no manual SQL.

## Known limitations

- SQLite deployment assumes a single node / single replica.
- Admin UI remains disabled by default, internal-network-only, and experimental.
- `202 Accepted` means the request was persisted, not that provider delivery
  completed.
- Delivery is at-least-once. If the service stops after provider send succeeds
  but before the database records delivery, the same mail may be sent again.
- Webhook endpoints are optional per tenant (one URL per tenant in this release).
- Consumer SDK status polling helpers are not yet included (HTTP GET is available;
  SDK Phase 2 follow-up).
- No template engine.
- No full multi-recipient support.
