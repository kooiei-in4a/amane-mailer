## Release boundary

v1.3.4 is planned as a **full service release**. The Git tag, GHCR image,
`Amane.Mailer.Contracts` NuGet package, OpenAPI version, CHANGELOG, release
record, and GitHub Release must describe one release version and one frozen
source identity.

The version-preparation branch and PR are not the final release authority. The
exact `releaseCommitSha` is frozen only after the reviewed version-preparation PR
is merged to `main`.

Relative to the published v1.3.1 service source, the changes leading into this
release are Release Engineering workflows, verification tooling, tests, and
documentation. There is no product feature, runtime semantic, database migration,
or public HTTP contract shape change. The migration inventory remains `001`
through `018`.

## Intermediate OCI-only history

- `1.3.2` was an OCI-only Release Engineering publication. Its public image was
  subsequently checked through the read-only verify-only recovery workflow. It
  did not advance the synchronized Contracts/OpenAPI/NuGet/Git-tag/GitHub-Release
  service identity beyond `1.3.1`.
- `1.3.3` was an OCI-only one-shot normal-path benchmark under Issue #659. It
  published and verified the `linux/amd64` image from source
  `c4819ea495e2f11cc6440fe499437cfa03aa2e5f` without recovery. It intentionally
  did not publish NuGet, a service Git tag, or a GitHub Release.

v1.3.4 resumes the repository versioning policy by synchronizing the applicable
full-service artifacts under `1.3.4`.

## Planned publication order

The current normal path is:

```text
frozen main
  -> GHCR v1.3.4 + immutable SHA tag
  -> public image verification
  -> Git tag v1.3.4 at the same releaseCommitSha
  -> Amane.Mailer.Contracts 1.3.4 + symbols from the release tag
  -> GitHub Release v1.3.4
  -> post-release documentation sync
  -> final cross-artifact verification
```

GHCR is first because `.github/workflows/publish-release-image.yml` is bound to
canonical `main` and requires the supplied source SHA to equal the workflow
commit. The release source must not be changed after any public artifact exists.

## Publication invariants

- Do not republish an existing `1.3.4` artifact.
- Do not overwrite or move an existing release tag.
- Do not overwrite GHCR version or immutable SHA tags.
- Do not publish `latest`.
- Dispatch a publish workflow exactly once; ambiguous dispatch results are
  resolved read-only before any next action.
- Preserve the `release` environment Human approval boundary.
- If image publication succeeds but post-publish verification fails, do not
  republish. Bind the original publication facts and use the existing read-only
  verify-only recovery path.

## Final evidence to record after publication

facts and record at minimum:

- GitHub Release identity and URL;

- confirmation that no same-version republish, tag overwrite, or `latest` tag was
