# v1.3.0 ADR amendment patch

- Status: Draft patch
- Date: 2026-08-05
- Scope: ADR 0012、0013、0014、0015、0020、0022
- Related: Draft ADR 0023、Issue #519

本書はAccepted ADRを直接変更しない。Koo承認後に各ADRへ適用する候補差分であり、今回の作業では既存ADRのStatusを変更しない。

## ADR 0012 proposed patch

- D-02: to、cc、bccは各0〜10件、全role合計1〜20件。Toが空でもCC／BCCがあれば受理可能。
- D-05: existing single-To hash vectorを不変とし、cc／bccの省略、null、空配列はhash documentからroleを省略。
- D-07: DeliveryUnknownを全requestのprovider submission uncertaintyへ一般化。automatic retry、whole-request manual retry、provider再呼出しを禁止。
- New D-07a: internal provider dispositionをDefinitelyNotSubmitted、Accepted、DefinitelyRejected、UnknownAfterSubmissionへ固定し、recipient summaryをrequest statusから分離。
- New D-07b: plain requestにもrequest単位submission evidenceを追加する。provider呼出し前にStartedをunique request_idでcommitし、Started以上のrecovery／manual retry／sweepはproviderを再呼出ししない。SMTPはStartedからDeliveryUnknown、ACSは保存済みoperation IDでbounded re-queryへ進む。

## ADR 0013 proposed patch

- bcc_recipient_revealをBCC専用capabilityとして追加。
- default deny、general operator deny、通常PII capabilityからの流用禁止。
- list、search、generic API、export、metrics、trace、logs、generic auditではraw BCCを返さず、件数だけを表示。
- auditにはadmin ID、tenant ID、request ID、日時、actionだけを記録し、raw BCCを記録しない。
- audit保存失敗、scope不明、capability不明はfail-closed。

## ADR 0014 proposed patch

- capability registryとgrant mappingへbcc_recipient_revealを追加。
- Admin sessionのtenant scopeとrecipient repository queryのtenant scopeを同時に強制。
- view_unmasked_list_piiだけではBCCをrevealできない。
- audit-before-serveのdurable saveをAdmin detailのserve gateにする。

## ADR 0015 proposed patch

- DeliveryUnknownをplain requestへ一般化した後も、DeliveryUnknownからQueuedへのmanual retryを許可しない。
- Failed／DeadLetteredの既存manual retryは、evidenceがNoEvidenceまたはDefinitelyNotSubmittedの場合だけ適用する。Started、Accepted、DefinitelyRejected、UnknownからQueuedへ戻さない。
- attachment requestの全terminal manual retry禁止はADR 0022の明示的例外として維持する。

## ADR 0020 proposed patch

- D-04: single mail_requests.recipient_email SOTを廃止し、mail_request_recipientsをrecipient correlationのcanonical sourceとする。
- D-05: recipient feedbackはcanonical rowとevent historyへ保存し、late feedbackでrequest statusを変更しない。
- D-06: BouncedとSuppressedをbounce event記録とsuppression登録の対象とする。Failed、Quarantined、unknown statusは記録のみ。
- v1.3はASCII-onlyのため、existing trim + full lowercase invariant normalizer、既存suppression row、既存keyを変更しない。IDNA、Punycode、re-key migrationは導入しない。
- correlationはprovider message ID exact match、request特定、event canonicalize、request配下address_key一意照合の順序とする。

## ADR 0022 proposed patch

- DeliveryUnknown一般定義の参照先をADR 0012／Draft ADR 0023へ移す。
- attachment固有のStarted marker、provider invocation最大1回、Started-only recovery、terminal後spool cleanup、全terminalからのmanual retry禁止を維持する。
- attachment requestはgeneral DeliveryUnknownの具体例であり、manual retry／spool再利用を許可する変更ではない。
- 添付なしrequestもprovider未提出を証明できない場合はDeliveryUnknownへ収束する。
